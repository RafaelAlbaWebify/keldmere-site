# Phase 3 — operator sales/delivery dry run

**Synthetic, internal-only training case**; not a Keldmere customer or a completed VERIDRA audit. No fabricated assessment result, price, acceptance or invoice may be recorded as actual.

## Representative customer need
An anonymised hypothetical small business requests advice about an existing three-page website, missing mobile clarity and weak contact enquiries. A URL, owner and site technology are intentionally **not specified**; VERIDRA cannot produce evidence until an actual permitted public site is selected.

## Acceptance steps
- [ ] Receive a test enquiry; confirm source, timestamp and legitimate purpose without sensitive personal data.
- [ ] Classify service type and capture business goal, access scope, URL, owner/authority, target audience and expected deadline.
- [ ] In local VERIDRA operator mode, audit a permitted **real public** URL. Save dated assessment/evidence ID, limitations and affected URLs. Do not mistake hypothetical symptoms for findings.
- [ ] Compare automated findings with manual review. Create candidate tasks with status `observed / needs verification / unknown / out of scope`.
- [ ] Record each selected task's deliverable, assumptions, estimated hours range and separately itemised expenses. If effort cannot be estimated, request discovery or quote assessment first.
- [ ] Produce a versioned **DRAFT** proposal containing exact scope, revisions, acceptance, excluded work, quote currency/tax status, payment and ownership/hosting responsibilities.
- [ ] Verify that unapproved proposals **cannot** become authorised delivery work. Document what the actual VERIDRA UI enforces.
- [ ] Record signed acceptance and payment only when genuine externally verified evidence exists; for this drill mark both as **NOT RECEIVED** and do not claim work started.
- [ ] Verify handover/report format using a synthetic internal artifact and redact anything client-sensitive.
- [ ] Record observations, defects, follow-up actions and screenshots in operator acceptance evidence. Do not check acceptance boxes without execution.

## Pass/fail criteria
Pass only if the full procedure is demonstrated in the actual local Windows operator application and no false client, acceptance or transaction is created. Passing Github Actions on Keldmere verifies documentation and static website only.

## Defects to log separately
- Public audit cannot be created from a lead or URL.
- Findings missing evidence/affected pages/uncertainty.
- Automatic priority mistaken for fixed quotation.
- No recorded proposal scope/version/approval reference.
- Work-start possible without verified acceptance.
- Inability to distinguish customer invoicing/payment from internal notes.
